Two Binding Mechanisms
Same flow, two data shapes
Both surface inside the same Connect data panel and produce automatic per-parent-row rendering. The builder picks whichever matches their collection schema.
Mechanism 1
Forward Reference
The parent collection owns an array or multi-reference field that directly points to child items. Picked via the new This item scope in the binding picker.
Meals

dishes[ ] field →
Dishes

Use when the parent owns the relationship — e.g. a "Meals" collection with a dishes multi-ref field.
Mechanism 2
Reverse Reference
The child collection holds a reference field pointing back to the parent. The system introspects the schema and wires a batched per-row filter automatically. Picked via the Related collections section.
Dishes
Child collection
← .meal ref field
Meals
Parent collection
Use when the child owns the reference — e.g. a "Dishes" collection with a meal field pointing to Meals. No parent field needed.
Both mechanisms: automatic per-row filtering · no manual dataset wiring · batched fetch (no N+1) · same inspector + cascade-disconnect model
4 / 13 Mechanism 1 · Happy Flow Drop nested repeater into outer item → Connect data → pick dishes[ ] from "This item" scope → canvas renders per-row children
5 / 13 Mechanism 2 · Happy Flow Drop nested repeater → Connect data → pick Related Collections → Dishes via meal → system auto-wires batched per-row filter
6 / 13 Sort & Filter · Mechanism 1 Open sort/filter on nested repeater bound via M1 → filters are scoped to the parent row's child array context
7 / 13 Sort & Filter · Mechanism 2 Sort and filter on nested repeater bound via M2 → filters apply on top of the auto-wired hasSome per-row filter
8 / 13 Item Limit & Performance Warning Configure item limit (default 10, range 1–100) → inspector shows outer × nested estimate → warning fires when combined total exceeds threshold
9 / 14 Disconnect & Replace — Cascade Warning Disconnect outer repeater → warning shows count of grandchild bindings affected → Cancel preserves everything / Confirm cascades the disconnect
10 / 14 Combined Bind CTA · One-click wire Select an unbound element inside the nested repeater → "Bind · [field] + Repeater → items" CTA appears → single click wires both the field binding and the repeater Items together
11 / 14 Edge Case · 4th Level Drop Blocked Try to drop a 4th-level repeater inside the 3rd-level template → drop is blocked → inspector surfaces depth limit message with explanation
12 / 14 Empty State · Outer Repeater Unbound Drop nested repeater before outer is connected → "Connect outer repeater first" state → nested repeater guides builder back to outer configuration

Binding & UX
FR-002
Auto-bind on drop
When a Repeater is dropped into a bound outer item, system auto-binds Items to the first available Child array — zero clicks needed.
FR-004
Inherited vs. directly attached context
Inspector context card visually distinguishes contexts inherited from the parent item vs. directly attached — two labelled groups.
FR-007
Replace outer repeater source
Warning before replacing (not just disconnecting) the outer's Items source — shows accurate grandchild binding count affected.
FR-008
Undo / recovery after disconnect
Persistent undo stack covers nested binding changes — builder can revert a cascade disconnect immediately.
Empty & Error States
FR-011
No child arrays available
When parent collection has no array/multi-ref fields AND no related collections exist — binding picker shows empty state with a path to modify the schema.
FR-012
Empty child array per parent row
A parent row whose child array has 0 entries renders an empty nested repeater area — layout does not collapse and other rows stay functional.
FR-013
Context mismatch indicator
Inspector flags when the nested repeater's Items source differs from its inherited parent context — e.g. a "Recommended" global list placed inside each row.
FR-014/15
AI-assisted binding
Builder describes the layout in natural language → AI agent creates and binds Outer + Nested Repeater → builder reviews and accepts before canvas commit.
